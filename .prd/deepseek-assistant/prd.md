## 功能标识

deepseek-assistant

## 问题背景

应用已有浏览器本地原料库存、自定义配方与内置酒谱，但定向检索未发现 DeepSeek/GLM 聊天或 AI 工具操作实现。用户希望用自然语言完成库存推荐、配方问答、替代原料建议、创作配方，并在确认后修改本地数据。库存仅表示原料有无，不记录数量。2026-10-14 用户要求同时兼容智谱 GLM 的 API Key，澄清后确定双 Key 各自保存、可切换当前服务。知识库 revision 2 的 K-001、K-005、K-007、K-009 等证据过期，本草稿以 2026-10-13～14 当前源码与文档回查为现状依据。

## 目标

- 根据当前浏览器库存、自定义酒单及内置酒谱进行连续调酒对话。

- 让用户核对 AI 提议的原料与配方变更，确认后持久化并反映到原有页面。

- 每位用户可分别配置自己的 DeepSeek Key 与智谱 GLM Key 并切换当前使用的服务；Key 与聊天记录保存在当前浏览器并可清除。

## 范围

### 本次包含

- 首页聊天侧栏与连续对话，聊天记录保存在当前浏览器并可清空。

- 读取当前库存、自定义配方及应用内置酒谱；库存推荐、配方问答、替代建议、创作配方。

- 确认后新增或编辑自定义配方、切换库存原料有无、新增原料、归档原料。

- 每位用户可分别填写自己的 DeepSeek Key 和智谱 GLM Key，浏览器保存、各自可清除，并可切换当前使用的服务，切换对下一次请求即时生效。

- AC-001～AC-007 功能验收已确认（含 GLM 兼容修订后的 AC-002、AC-007，见 DEC-014）；性能指标待实测后确定。

### 本次不包含

- 删除原料或配方。

- 修改内置酒谱原始数据；内置酒谱的改编以新自定义配方表达。

- 库存余量管理、自动扣减数量、账号系统和跨设备云同步。

- AI 图片生成或图片内容识别；本次按文本配方数据开展。

## 验收标准

### AC-001

**关联需求**

- REQ-001

**前置条件**

**触发**

**可观察结果**

记录按顺序恢复，可继续对话；清空后历史不再展示或进入新对话上下文；库存、配方、Key 不被聊天清空操作修改。

**验证方案**

场景验证恢复、追问、空历史、清空；检查各存储项。用户已确认此验收；本轮未执行业务验证。

### AC-002

**关联需求**

- REQ-002

**前置条件**

用户未配置 Key，或已保存 DeepSeek、GLM 之一或两者的个人 Key。

**触发**

分别输入 DeepSeek Key 与 GLM Key、刷新，切换当前服务发送请求；再清除其中一个 Key 并发送新请求。

**可观察结果**

两个 Key 可分别在本浏览器恢复，界面默认遮蔽；切换即时生效，后续请求使用所选服务；被清除 Key 的服务要求重新配置，另一 Key、酒单和聊天不受影响；请求上下文、URL 和日志均无密钥文本。

**验证方案**

检查配置状态、本地存储、切换后的模型请求体（上游地址与认证头随服务变化）与应用日志；不在验证报告输出真实 Key。原始单服务验收与双 Key/切换行为均已获用户确认（DEC-010、DEC-014）；本轮未执行业务验证。
