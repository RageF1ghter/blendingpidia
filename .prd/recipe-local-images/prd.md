## 问题背景

用户希望新增 recipe 的图片与内置配方图片一样保存为项目中的真实文件。当前 app/page.tsx 的新增/编辑表单只接受图片 URL，配方记录通过 saveAppStorage 写入浏览器 localStorage；内置目录通过 tools/cocktail-catalog-plugin.ts 在开发期生成资源 URL、构建期输出静态图片。知识库 K-003～K-006 的相关证据已变化，本方案以当前源码回查为依据。用户已选择项目磁盘存储、选择本地图片且兼容旧 URL、首期本机运行且部署版保留 URL。

## 目标

- 本机新增和编辑自建配方时，可选择图片并保存为项目内的真实文件。
- 刷新页面及重启本机服务后，已有配方仍能通过稳定 URL 读取磁盘图片。
- 保留旧图片 URL 和无图片配方的兼容行为，部署版继续使用 URL。

## 范围

### 本次包含

- 本机 npm run dev 模式的图片选择、预览、上传、读取、替换和解除引用。
- 候选方案：新增 Node/Vite 本机中间件负责文件读写，建议目录 resource/user-recipe-images/；此目录位于内置目录之外，不触发其 full-reload 监听。
- 候选方案：首期配方正文仍保存于现有 localStorage，仅图片文件落盘。
- 候选方案：每个 recipe 一张可选图片，支持 JPEG、PNG、WebP，首期保留原文件，不增加裁剪或压缩。

### 本次不包含

- 部署版图片上传、云存储和自动同步。
- 将自建配方正文写入内置 recipe data.json 或加入内置目录。
- 旧远程 URL 自动下载；多图相册；导出与分享。
- 候选方案：自动删除历史图片及跨浏览器垃圾回收；npm run start 的 Worker 本地预览磁盘写入。
